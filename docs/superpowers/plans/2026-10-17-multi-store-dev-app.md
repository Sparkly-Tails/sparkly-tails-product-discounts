# Multi-Store Dev App Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the dev app a regular multi-store app: the shop comes from the verified login, the tier checkout discount is created by the app, all stored data lives in `$app:smooth_discount`, and stores are provably isolated.

**Architecture:** One pure module holds the metafield names; writers, Functions and Liquid all read them. The proxy verifies the ID token for any `*.myshopify.com` shop and forwards the verified shop; one helper hands that shop to `getAccessToken` and `shopifyQuery`. Webhooks take the shop from the signed body. `ensureTierDiscount` creates the tier discount once per store.

**Tech Stack:** Next.js 16 / TypeScript (vitest), Prisma sessions, Shopify Admin GraphQL, Shopify Functions (Rust, GraphQL input queries), theme app extension (Liquid, plain JS tested with `node --test`).

**Spec:** `docs/superpowers/specs/2026-10-17-multi-store-dev-app-design.md` (read it first: it holds the reasons, the verified facts and the owner's decisions).

## Global Constraints

- **Branches:** all work PRs target `milestone/multi-store-install` (never `dev`, never `main`). Each task: `git fetch origin`, cut `feat/multi-store-<topic>` from `origin/milestone/multi-store-install`, one atomic commit (or a few tightly related), check `gh pr list --head <branch> --state all` before every push, open the PR into the milestone, non-author review, the owner merges. If `dev` moved, merge `origin/dev` into the milestone branch (no rebase, no force push).
- **Commit rules:** every commit leaves `npx tsc --noEmit`, eslint on touched files, the whole `npx vitest run` (one process) and `node --test extensions/product-tier-pricing-tests/*.test.js` green; code commits bump the version (`npm version <v> --no-git-tag-version`; current `0.23.12`: Task 2 `0.23.13`, 3 `0.23.14`, 4 `0.23.15`, 5 `0.23.16`, 6 `0.23.17`, 7 `0.23.18`, 8 `0.23.19`, 9 `0.23.20`, 10 `0.23.21`; docs-only commits skip it); commit messages carry no AI attribution at all (no `Co-Authored-By` trailer, no "generated by" line, nothing saying an AI wrote the code): the owner's global rule.
- Pure functions: pass values in as arguments; no closing over outer-scope state. No hardcoded colours. In vitest `beforeEach` use block bodies. Each shell: `source ~/.nvm/nvm.sh && nvm use 22.23.3`.
- Namespace `$app:smooth_discount`; keys exactly: `tier_config` (shop), `tier_discount`, `tier_sibling_products`, `tier_sibling_variants`, `time_discount` (product), `time_config` (shop), `time_function_config` (discount). Fallback only if Task 1 says so: bare `$app` with keys `smooth_discount_<key>`.
- Tier Function handle `product-discount`; discount input is `title: "Product tier discounts"`, `startsAt` now, `discountClasses: [PRODUCT]`, no `combinesWith`.
- Shop host rule: `^[a-z0-9][a-z0-9-]*\.myshopify\.com$`, https only. No `SHOPIFY_SHOP` anywhere in `src/` or `scripts/`.
- Merging and `shopify app deploy --config shopify.app.dev.toml` are the owner's actions. Never touch production data; never print secrets or tokens. The second dev store exists (owner's); the dev app must be installed on it before Task 10.

## Review Focus

1. **A request with no verified shop** (static asset, forged `x-shopify-shop`, a script) reaches `shopifyQuery`: it must throw, never fall back to an environment shop or another store. Pinned in Task 7.
2. **Two requests for stores A and B interleaved in one server instance:** each uses its own session and token. Pinned in Task 7.
3. **A valid webhook body for store A replayed with store B's header:** nothing happens to B. Pinned in Task 8.
4. **Two tabs open the app at once on a new store, and a store whose tier discount is paused or expired:** exactly one discount is created; an existing one is never modified or duplicated. Pinned in Task 9.
5. **Look-alike shop hosts** (`myshopify.com`, `evil.myshopify.com.attacker.com`, `shop.myshopify.com:8080`, `http://shop.myshopify.com`) are refused at login. Pinned in Task 6.
